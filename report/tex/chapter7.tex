\chapter{AI-Assisted Features}
\label{ch:ai}

Sarabo uses Google Gemini in four places. In all of them the same idea applies: the AI \emph{suggests}, and a person \emph{decides}. Nothing the AI returns can change a price, a payment or the state of a request unless a person has reviewed it. All four features are off by default and only work once they are turned on in the settings and an API key is supplied. The client calls \texttt{GET /ai/status} and hides any feature that is not available. The main model is \texttt{gemini-3.5-flash-lite}. When it is slow, overloaded or rate-limited, \texttt{gemini-3.1-flash-lite} is used instead.

\section{AI Customer Support Chat}
Every page has a chat that answers questions about how Sarabo works, what services it offers and what they usually cost. The prompt is built from the \emph{live} catalogue (\texttt{supportKnowledgeService}), so the prices it mentions are always up to date. The length of the history, of each message and of each answer is capped. The follow-up buttons (View services, Track a request, Log in and Create an account) come from a fixed list, so the AI never makes up links (Figure~\ref{fig:wt-p05}).

\section{AI Request Helper}
On the request form, the customer can describe the problem in Bangla, in English or in a mix of the two (``Banglish''), add a photo of the damage, or do both. The AI then drafts the device, the catalogue service, the brand, the model and an English description. It also gives a confidence level, may ask a follow-up question, and for a photo says whether it actually shows a device. The form fills itself in, the customer can change anything, and \emph{Undo} brings back the previous values (Figure~\ref{fig:wt-c02}). If the photo shows a device, it is kept with the request's other photos and sent when the customer presses ``Upload'', so they do not have to pick it a second time.

\section{Technician Price Guide and AI Offer Note}
The price guide does not use AI at all. It shows the usual price range from real offers made for the same service over the last 180 days, running from the 25th percentile of the ``from'' prices to the 75th percentile of the ``to'' prices, and it does the same for fees. If there are fewer than three offers, it uses the catalogue range instead. An offer that falls far outside the guide gets a warning, but the technician can still send it.

The technician can also ask the AI to write the offer note, in English or in Bangla. The model is given only what the technician can see: the device, the repair, the problem description and whether there are photos. It writes in the technician's voice, describes the likely issue only as a possibility, says that the final price will be set after inspection, and uses no numbers. Phone numbers (Bangla digits included), emails, links and social media handles are removed from the note, so all contact stays on the platform (Figure~\ref{fig:wt-t03}).

\section{AI Summary of Admin Reports}
\label{sec:aisummary}
The Reports page (for 7, 30 or 90 days, see Section~\ref{sec:reports}) can show an AI summary made up of a headline, two to four highlights and one to three suggested actions. The model only receives totals: requests made, finished and cancelled, the success rate, the average number of days, refused requests by region, the top devices and repairs, technician workload, inspection-fee money and the attention counts. It never receives names, emails or IDs. The most recent summary for each period is saved, so opening it again costs nothing (Figure~\ref{fig:wt-a08}).

\section{Safeguards}
Table~\ref{tab:aisafety} sums up how Sarabo deals with the main risks of features built on LLMs~\cite{owaspllm}, and Table~\ref{tab:ailimits} gives the default usage limits.

\begin{table}[htbp]
\centering
\caption{AI risks and safeguards}
\label{tab:aisafety}
\small
\begin{tabularx}{\textwidth}{@{}p{3.4cm}X@{}}
\toprule
\textbf{Risk} & \textbf{Safeguard in Sarabo} \\
\midrule
Invented catalogue items & The request helper must answer with IDs from an enum built from the live catalogue (JSON schema); the server re-checks them and drops unknown or inactive IDs, or a repair belonging to another device. \\
Invented prices & No AI feature ever sets a price. Estimates come from the catalogue; the offer note contains no numbers. \\
Invented statistics & Every sentence of the report summary is checked: each number must appear in the facts, be a difference or rounded percentage between periods, a small count up to 10, or a fixed context number. Failing sentences are dropped; if nothing remains, the request fails with 502. \\
Prompt injection & Customer text is marked as untrusted data in the prompt, and output is forced into a schema. \\
Personal data leakage & Text containing a card number, password, token or tracking code is refused before any AI call. Models receive no names, emails or addresses. Contact details are stripped from generated notes. \\
Unbounded cost & Per-user 10-minute and daily limits plus a site-wide daily budget per feature, stored in MongoDB so all serverless instances share them. If the database is unreachable, the feature fails closed. \\
Bad photos & JPEG/PNG/WebP only, at most 1.5\,MB, first bytes must match the type; the client shrinks photos to 1024\,px first. The helper's photo is not stored by the AI endpoint. \\
Provider failure & If the first model is slow (over 5\,s for support), overloaded or rate-limited, the request goes straight to the fallback model; otherwise controlled errors (503 unavailable, 504 timeout, 502 invalid answer) and the rest of the form keeps working. Live support answers take 1.4--1.9\,s. \\
\bottomrule
\end{tabularx}
\end{table}
