\chapter{Limitations and Future Work}
\label{ch:limitations}

\section{Current Limitations}

\subsection{Manual Technician Payouts}
The wallet tracks earnings and withdrawals precisely, but the money itself is sent by an admin using bKash ``Send Money'', who then records the transaction ID. The platform does not yet pay technicians automatically through a bKash, Nagad or bank API.

\subsection{Card Payments in Test Mode}
Customer payments use Stripe in test mode. Stripe does not offer local accounts for businesses in Bangladesh, so a real launch would need a local gateway such as SSLCOMMERZ or bKash Payment Gateway behind the same payment service interface.

\subsection{Pickup Capacity Is Checked, Not Locked}
Slot capacity is counted before a request is saved but is not locked, so two customers booking the last place in the same second could both succeed. At the current scale this is acceptable (admins see every pickup time), but a busy service would need an atomic slot counter.

\subsection{Provisional Catalogue Prices}
The 45 services and their estimate ranges are a starting point for demonstration, not prices reviewed or approved by a real repair business. Admins can change them at any time.

\subsection{Single Active Job per Technician}
A technician is either available or busy with one repair. This prevents double booking but does not model technicians who can handle several small jobs per day.

\subsection{Legacy Internal Values}
Some stored role and status values (\texttt{rider}, \texttt{parcel\_delivered}, and others) are inherited from the original parcel-delivery codebase. They are hidden from users, but a dedicated migration would make the data model cleaner.

\subsection{Not Yet Used by Real Customers}
The platform is deployed and tested, but it has not been run with real customers, technicians and money, and it has not undergone load testing or an external security audit.

\section{Future Enhancements}
\begin{enumerate}
  \item \textbf{Local payment gateway and automated payouts}: integrate SSLCOMMERZ or bKash for customer payments and technician disbursement, with reconciliation.
  \item \textbf{Live technician location}: show the technician's approach on a map on pickup day.
  \item \textbf{Mobile apps or a Progressive Web App}: offline-friendly technician app with push notifications.
  \item \textbf{SMS notifications}: many customers in Bangladesh rely on SMS more than email.
  \item \textbf{Warranty and returns}: post-repair warranty cases with evidence and re-inspection.
  \item \textbf{Parts inventory}: track parts used, their cost and supplier per repair.
  \item \textbf{Technician scheduling}: daily capacity, working hours and route-aware assignment.
  \item \textbf{Smarter matching}: rank offers using ratings, distance, response time and completion history.
  \item \textbf{Bangla interface}: full Bangla localisation of the user interface, not only of AI input.
  \item \textbf{Schema clean-up}: retire the remaining legacy values through a planned data migration.
\end{enumerate}
