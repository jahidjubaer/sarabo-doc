১. AI ব্যবহার নিয়ে প্রশ্ন

স্যারকে সৎভাবে বলবে, এটা ভালো সিদ্ধান্ত। তবে নিচের উত্তরগুলো নমুনা মাত্র: তোমার ক্ষেত্রে যেটুকু সত্য শুধু সেটুকুই বলবে, নিজের ভাষায়। এরপর স্যার যাচাই করবেন তুমি বোঝো কি না, তাই বাকি অংশগুলোই আসল প্রস্তুতি।

★ এই project-এ AI কতটা ব্যবহার করেছ?

সরাসরি বলো: code লেখায় অনেকটাই AI-এর সাহায্য নিয়েছি। Project-এর idea, কোন feature থাকবে, কোন নিয়ম চলবে, এগুলো আমি ঠিক করেছি, চালিয়ে পরীক্ষা করেছি, আর ভুল পেলে ঠিক করিয়েছি। শতাংশ বানিয়ে বলবে না।

★ AI যদি code লেখে, তাহলে তুমি কী শিখলে?

পুরো system কীভাবে একসাথে কাজ করে: request কীভাবে চলে, auth কীভাবে হয়, data কোথায় থাকে, payment কীভাবে confirm হয়। প্রতিটা line নিজে হাতে লিখিনি, কিন্তু design আর flow বুঝিয়ে বলতে পারি। আপনি যেকোনো অংশ খুলে জিজ্ঞেস করতে পারেন।

★ AI ভুল করলে কীভাবে ধরলে?

Automated test, browser-এ নিজে চালিয়ে দেখা, আর CI। উত্তরে তোমার নিজের দেখা একটা বাস্তব ঘটনা বলো, যেটা সত্যি ঘটেছে। আগে থেকে একটা ঠিক করে রাখো।

এখন AI ছাড়া একটা ছোট CRUD API বানাতে পারবে?

পারলে হ্যাঁ বলো, আর viva-র আগে একবার করে দেখো: Express route, MongoDB insert/find, একটা React form। না পারলে সৎভাবে বলো কোন অংশে আটকাবে। স্যার সামনে করতে বলতে পারেন।

তোমার project-এও তো AI feature আছে। সেটা আর code লেখায় AI, দুটো কি এক?

না। Project-এর ভেতরে Google Gemini চলে (request form draft, support chat, report summary)। আর development-এ AI ছিল coding সহকারী। এই দুটো আলাদা করে বলবে।

৩. Authentication: JWT ও Firebase

★ JWT কী? এর ভেতরে কী থাকে?

JSON Web Token: header.payload.signature। Header-এ algorithm, payload-এ claim (email, expiry), signature দিয়ে প্রমাণ হয় token বদলানো হয়নি। Server token store না করেই যাচাই করতে পারে।

★ JWT কি encrypted? Payload-এ password রাখা যায়?

না, সাধারণ JWT শুধু signed, encrypted নয়। Payload base64url, যে কেউ decode করে পড়তে পারে। তাই গোপন কিছু রাখা যাবে না। Signature শুধু পরিবর্তন ধরে।

★ Firebase ব্যবহার করলে, তাহলে কি JWT ব্যবহার করোনি?

করেছি। Firebase ID token নিজেই একটা JWT, মেয়াদ ১ ঘণ্টা। পার্থক্য হলো token বানায় Firebase, আমার server নয়। আমি নিজে jwt.sign() করি না; server admin.auth().verifyIdToken() দিয়ে যাচাই করে।

★ নিজের JWT না বানিয়ে Firebase কেন?

নিজে করলে password hashing, email verification, password reset, Google login, token refresh, key management সব লিখতে ও সুরক্ষিত রাখতে হতো। Firebase-এ এগুলো তৈরি আর free। Password আমার database-এ থাকেই না, তাই ফাঁস হওয়ারও ভয় নেই। ক্ষতি: Google-এর service-এর উপর নির্ভরতা।

★ পুরো login flow বলো।

Client: Firebase SDK দিয়ে sign in → ID token পায় Client: useAxiosSecure interceptor → Authorization: Bearer <token> Server: verifyFBToken → verifyIdToken() → req.decoded_email Server: verifyAdmin / verifyTechnician → users collection থেকে role চেক Server: controller কাজ করে → response

★ Authentication আর authorization-এর পার্থক্য?

Authentication: তুমি কে (token যাচাই, ব্যর্থ হলে 401)। Authorization: তোমার অনুমতি আছে কি না (role, ownership, ব্যর্থ হলে 403)।

Session-based আর token-based auth-এর পার্থক্য?

Session: server state রাখে, browser-এ শুধু session id (সাধারণত cookie)। Token: তথ্য token-এই থাকে, server কিছু রাখে না, তাই stateless ও serverless-এ সুবিধা। Session সহজে সাথে সাথে বাতিল করা যায়, JWT যায় না।

★ Logout করলে JWT কি সাথে সাথে invalid হয়?

না। Client token ফেলে দেয়, কিন্তু কেউ কপি করে থাকলে মেয়াদ শেষ পর্যন্ত (১ ঘণ্টা পর্যন্ত) চলবে। আমার code-এ verifyIdToken revocation চেক করে না। দরকার হলে checkRevoked: true দেওয়া যায়, তবে প্রতি request-এ বাড়তি network call হবে।

Token-এর মেয়াদ শেষ হলে কী হয়? Access আর refresh token কী?

Access token স্বল্পমেয়াদি, refresh token দিয়ে নতুন access token আনা হয়। Firebase SDK এটা নিজেই করে: getIdToken() মেয়াদ শেষের কাছাকাছি হলে refresh করে। তবু 401 এলে আমার interceptor একবার forced refresh করে retry করে, এরপরও ব্যর্থ হলে logout।

Token কোথায় রাখা উচিত? localStorage না cookie?

localStorage XSS-এ পড়া যায়। httpOnly cookie JS পড়তে পারে না, কিন্তু CSRF protection লাগে। আমার ক্ষেত্রে Firebase SDK নিজে browser storage-এ (default IndexedDB) রাখে, আর token যায় header-এ। Cookie ব্যবহার করি না, তাই CSRF-এর ঝুঁকি কম, কিন্তু XSS থেকে সাবধান থাকতে হয়।

Server প্রতিবার token যাচাই করতে Google-কে call করে?

না। Firebase token RS256-এ signed: Google private key দিয়ে sign করে, আর Admin SDK Google-এর public key (cache করা) দিয়ে নিজেই যাচাই করে। Signature, expiry, audience, issuer সব চেক হয়।

HS256 আর RS256-এর পার্থক্য?

HS256 symmetric: একই secret দিয়ে sign ও verify। RS256 asymmetric: private key দিয়ে sign, public key দিয়ে verify, তাই যাচাইকারী token বানাতে পারে না।

★ Role JWT-তে রাখোনি কেন? Database-এ কেন?

Firebase custom claim-এ রাখা যেত, তাহলে প্রতিবার DB read লাগত না। কিন্তু token-এ থাকলে role বদলালে পুরনো token মেয়াদ পর্যন্ত পুরনো role বহন করে। DB-তে রাখায় পরিবর্তন সাথে সাথে কার্যকর। ক্ষতি: admin/technician route-এ একটা বাড়তি query।

Client-এর AdminRoute থাকলে server-এ verifyAdmin কেন?

Client route guard শুধু UI লুকায়; Postman দিয়ে সরাসরি API call করা যায়। আসল নিরাপত্তা server-এ।

Firebase-এর web apiKey client-এ দেখা যায়। সমস্যা না?

না। এটা project চেনার জন্য, গোপন key নয়। গোপন হলো server-এর service account key (FB_SERVICE_KEY), যেটা শুধু server-এর env-এ থাকে। Admin SDK সেটা দিয়ে চলে।

Email verification কীভাবে enforce করেছ?

Decoded token-এর email_verified দেখে verifyEmailVerified middleware; না হলে 403। Client-এর পাঠানো কোনো flag বিশ্বাস করি না।

৪. JavaScript

★ var, let, const-এর পার্থক্য?

var function-scoped, hoisted হয়ে undefined পায়। let/const block-scoped, declare-এর আগে ব্যবহার করলে error (Temporal Dead Zone)। const reassign করা যায় না, তবে object-এর ভেতরের মান বদলানো যায়।

★ Closure কী? একটা উদাহরণ দাও।

Function তার তৈরি হওয়ার জায়গার variable মনে রাখে, বাইরের function শেষ হলেও। উদাহরণ: useAxiosSecure-এর interceptor; আর React-এর "stale closure" সমস্যা। আমার interceptor পুরনো user ধরে রাখছিল বলে auth.currentUser পড়ে।

★ Event loop কী?

JavaScript single-threaded। Call stack খালি হলে আগে সব microtask (Promise), তারপর একটা macrotask (setTimeout, I/O callback) চলে। এভাবে thread আটকে না রেখে async কাজ হয়।

এই code-এর output কী?

console.log(1); setTimeout(() => console.log(2), 0); Promise.resolve().then(() => console.log(3)); console.log(4);

1 4 3 2। আগে sync কোড, তারপর microtask, তারপর timer।

★ Promise আর async/await কী?

Promise ভবিষ্যৎ ফলের object: pending, fulfilled, rejected। async/await Promise-এর উপরেই সহজ syntax; await ঐ function থামায়, পুরো thread নয়। Error ধরতে try/catch। আগে callback nesting-এর সমস্যা ছিল (callback hell)।

Promise.all আর Promise.allSettled-এর পার্থক্য?

all একটা fail করলেই পুরোটা reject। allSettled সবার ফল দেয়, সফল বা ব্যর্থ। পরস্পর নির্ভরশীল না হলে parallel চালালে সময় বাঁচে।

== আর ===?

== type বদলে তুলনা করে ("5" == 5 true), === type-সহ (false)। সবসময় === ব্যবহার করা ভালো।

null আর undefined?

undefined: মান দেওয়া হয়নি। null: ইচ্ছা করে "কিছু নেই"। AuthProvider-এ দুটোর আলাদা অর্থ আছে: undefined মানে এখনও জানা নেই, null মানে signed out।

Arrow function আর সাধারণ function-এর পার্থক্য?

Arrow-র নিজের this ও arguments নেই, বাইরেরটা নেয়; new দিয়ে চলে না। সাধারণ function-এ this নির্ভর করে কীভাবে call হলো তার উপর।

Hoisting কী?

Declaration আগে memory-তে নেওয়া হয়, তাই function declaration লেখার আগেই call করা যায়। var পায় undefined, let/const TDZ-তে থাকে।

Prototype কী?

JS-এর inheritance পদ্ধতি। Object-এ property না পেলে prototype chain ধরে খোঁজে। class এর উপরেই syntax। আমার RepairRequestModel একটা class।

Spread, destructuring, optional chaining কী?

{...a} কপি/merge। const { user } = useAuth() বের করে আনা। error.response?.status null হলে crash না করে undefined দেয়।

Shallow copy আর deep copy?

Shallow শুধু উপরের স্তর কপি করে, ভেতরের object একই reference। Deep সব স্তর (structuredClone)। React state বদলাতে এটা জরুরি, কারণ React reference তুলনা করে।

map, filter, reduce, forEach?

map রূপান্তর করে নতুন array, filter বাছাই, reduce এক মানে আনে (যেমন total), forEach শুধু loop, কিছু return করে না।

CommonJS আর ES Module?

require/module.exports বনাম import/export। আমার server CommonJS, client ES Module ("type": "module")। ESM static, তাই tree-shaking ভালো হয়।

Debounce কী?

পরপর আসা call-এর শেষটা কিছুক্ষণ পরে একবার চালানো; যেমন search-এ প্রতি অক্ষরে API call না করা।

৫. Node.js

★ Node.js কী? এটা কি language বা framework?

কোনোটাই না। Node হলো JavaScript runtime: V8 engine + libuv, যা browser-এর বাইরে JS চালায় এবং file, network access দেয়।

★ Node single-threaded হয়ে অনেক request কীভাবে সামলায়?

Non-blocking I/O। DB বা network call শুরু করে অপেক্ষা না করে পরের request ধরে; কাজ শেষ হলে event loop callback চালায়। JS এক thread-এ চলে, তবে libuv-এর thread pool আর OS I/O-র কাজ করে।

তাহলে Node কোন কাজে খারাপ?

CPU-ভারী কাজ (video encoding, বড় হিসাব), কারণ event loop আটকে যায়। সমাধান worker threads বা আলাদা service। আমার project I/O-ভারী, তাই মানানসই।

Blocking আর non-blocking code-এর উদাহরণ?

fs.readFileSync শেষ না হওয়া পর্যন্ত সব আটকে রাখে; await fs.promises.readFile রাখে না।

package.json আর package-lock.json-এর পার্থক্য?

package.json-এ চাহিদা ও script; lock file-এ সব dependency-র হুবহু version, যাতে সব জায়গায় একই install হয়। dependencies production-এ লাগে, devDependencies শুধু development-এ।

^5.1.0 মানে কী?

Semantic versioning: major.minor.patch। ^ মানে একই major-এ নতুন minor/patch চলবে (<6.0.0)।

Environment variable কেন? .env commit করো?

Secret আর environment অনুযায়ী config code-এর বাইরে রাখতে। .env commit হয় না, .env.example-এ শুধু নামগুলো থাকে। Production-এ Vercel-এর settings-এ।

Buffer আর Stream কী?

Buffer: raw bytes। Stream: data টুকরো টুকরো পড়া, পুরোটা memory-তে না এনে। Stripe webhook-এ raw Buffer লাগে signature যাচাইয়ের জন্য।

৬. Express.js

★ Express কী? Node থাকতে Express কেন?

Node-এর উপর ছোট web framework। শুধু Node-এর http দিয়ে URL parsing, routing, body parsing নিজে করতে হতো; Express-এ routing আর middleware তৈরি।

★ Route কী? Parts গুলো বলো।

app.post('/repair-requests/:id/quote/decision', verifyFBToken, ensureDatabaseReady, verifyEmailVerified, (req, res) => quoteController.decideQuote(req, res));

HTTP method + path + middleware chain + handler। :id হলো route parameter। বাম থেকে ডানে চলে; একটা response দিয়ে দিলে পরেরগুলো চলে না।

★ Middleware কী? next() কী করে?

Request আর response-এর মাঝের function, (req, res, next)। next() পরের ধাপে পাঠায়, না ডাকলে আর response না দিলে request ঝুলে থাকে। আমার উদাহরণ: requestId, verifyFBToken, verifyAdmin, rate limiter।

req.params, req.query, req.body?

Params: /requests/:id এর মান। Query: ?status=open। Body: POST/PATCH-এর JSON, express.json() parse করে দেয়।

app.use আর app.get?

app.use সব method-এ, path prefix মিলিয়ে চলে। app.get শুধু GET-এ, পুরো path মিলিয়ে।

★ Middleware-এর order কেন গুরুত্বপূর্ণ? উদাহরণ দাও।

Express যে ক্রমে register হয় সে ক্রমে চালায়। Stripe webhook route express.json()-এর আগে, কারণ signature যাচাইয়ে আসল raw bytes লাগে; একবার parse হলে আসল bytes আর পাওয়া যায় না। Auth আগে, DB check পরে, যাতে ভুল token দ্রুত 401 পায়।

Error-handling middleware কেমন হয়?

চারটা argument: (err, req, res, next), সব route-এর পরে register করতে হয়। Express 5-এ async handler-এর rejected Promise নিজে থেকে error handler-এ যায়; Express 4-এ হাতে next(err) দিতে হতো। আমার index.js-এ CORS error-এর জন্য একটা আছে।

express.Router() কী? তুমি ব্যবহার করেছ?

Route গুলো আলাদা ফাইলে ভাগ করার mini app। আমি একটু ভিন্নভাবে করেছি: প্রতিটা routes/*.js একটা function export করে, userRoutes(app, controllers), যেটা সরাসরি app-এ register করে। উদ্দেশ্য একই।

trust proxy কেন দিয়েছ?

Vercel-এর পেছনে থাকায় আসল client IP থাকে X-Forwarded-For header-এ। Rate limiter-এর জন্য আসল IP লাগে। 1 মানে একটা proxy hop বিশ্বাস করি; true দিলে IP জাল করা সহজ হতো।

express.json()-এর limit কত? কেন বদলেছ?

Default 100 kB। শুধু /ai/request-draft-এ 2.5 MB, কারণ সেখানে base64 ছবি আসে। Limit থাকলে বিশাল body পাঠিয়ে server-কে ক্ষতি করা কঠিন।

৭. HTTP ও REST

★ REST কী? এর নিয়মগুলো?

API ডিজাইনের ধরন: URL resource বোঝায়, HTTP method কাজ বোঝায়, stateless, client-server আলাদা। আমার API মূলত RESTful; /accept-এর মতো action path পুরোপুরি REST-সম্মত নয়, তবে পড়তে স্পষ্ট।

★ GET, POST, PUT, PATCH, DELETE-এর পার্থক্য? PUT আর PATCH?

পড়া, তৈরি, পুরোটা বদল, আংশিক বদল, মোছা। GET, PUT, DELETE idempotent; POST নয়।

★ Status code: 200, 201, 400, 401, 403, 404, 409, 429, 500, 503?

OK; created; ভুল input; login নেই; অনুমতি নেই; নেই; state conflict; অতিরিক্ত request; server error; service সাময়িক অনুপলব্ধ। 401 আর 403-এর পার্থক্য নিশ্চিত বলতে পারবে।

★ Browser-এ URL লিখে Enter চাপলে কী হয়?

DNS থেকে IP → TCP connection → TLS handshake → HTTP request → server response → HTML parse, CSS/JS load → render। আমার site-এ Vercel index.html দেয়, তারপর React চালু হয়ে API call করে।

★ CORS কী? এটা কি server-কে রক্ষা করে?

Browser-এর নিয়ম: অন্য origin-এর response পড়তে server-এর অনুমতি লাগে। Client আর API আলাদা domain, তাই config/cors.js-এ allow-list। এটা শুধু browser-এর জন্য; Postman বা curl আটকায় না। আসল সুরক্ষা token।

Preflight request কী?

Authorization header বা JSON body থাকলে browser আগে OPTIONS পাঠিয়ে জেনে নেয় অনুমতি আছে কি না, তারপর আসল request পাঠায়।

HTTP আর HTTPS?

HTTPS = HTTP + TLS: encryption, integrity, server-এর পরিচয় প্রমাণ। Bearer token পাঠানোর জন্য অপরিহার্য।

Stateless মানে কী? কেন ভালো?

Server আগের request মনে রাখে না, সব তথ্য প্রতিটা request-এ। যেকোনো instance যেকোনো request সামলাতে পারে, তাই scale সহজ।

REST আর GraphQL? REST কেন?

GraphQL-এ client ঠিক করে কোন field লাগবে, একটা endpoint। REST সহজ, HTTP cache চলে, আর আমার দরকার মিটিয়েছে।

৮. React

★ React কী? Library না framework?

UI বানানোর library। Component দিয়ে declarative UI। Routing বা data fetching নিজে দেয় না, তাই আলাদা library নিয়েছি।

★ Virtual DOM ও reconciliation কী?

Render-এ UI-এর হালকা JS tree তৈরি হয়, আগের tree-র সাথে diff করে শুধু বদলানো অংশ আসল DOM-এ যায়। আসল DOM update তুলনামূলক খরচের।

★ Props আর state-এর পার্থক্য?

Props বাইরে থেকে আসে, read-only। State component-এর নিজের, বদলালে re-render হয়।

★ useState আর useEffect কী? Dependency array-র তিন রূপ?

State রাখা, আর render-এর পরে side effect চালানো। Array নেই: প্রতি render-এ। []: mount-এ একবার। [x]: x বদলালে। Cleanup function unmount-এ বা পরের effect-এর আগে চলে, যেমন onAuthStateChanged unsubscribe আর interceptor eject।

★ Hook-এর নিয়ম কী? Custom hook কী?

শুধু top level-এ আর component/custom hook থেকে call; condition বা loop-এ নয়, কারণ React call-এর ক্রম দিয়ে state মেলায়। Custom hook হলো use নামের function যা logic আবার ব্যবহার করে: useAuth, useRole, useAxiosSecure।

List-এ key কেন লাগে? Index দিলে সমস্যা কী?

Key দিয়ে React চেনে কোন item কোনটা। Index দিলে order বদলালে ভুল item-এ state যুক্ত হতে পারে; তাই stable id ভালো।

useMemo, useCallback, useRef?

useMemo হিসাবের ফল মনে রাখে, useCallback function-এর reference। useRef এমন মান রাখে যা বদলালে re-render হয় না, বা DOM element ধরে; AuthProvider-এ আগের uid রাখতে ব্যবহার করেছি।

★ Context API কী? Redux কেন নাওনি?

Prop drilling ছাড়া data পৌঁছানো। আমি auth আর theme-এ Context ব্যবহার করেছি। বেশিরভাগ data server থেকে আসে, সেটা TanStack Query সামলায়। তাই Redux-এর আলাদা global store লাগেনি। Context-এর value বদলালে সব consumer re-render হয়, তাই ঘন ঘন বদলানো data-র জন্য ভালো নয়।

★ TanStack Query কী করে? useEffect-এ fetch করলে কী সমস্যা?

useEffect-এ loading, error, cache, race condition সব হাতে লিখতে হয়। Query-তে queryKey দিয়ে cache, আর mutation-এর পরে invalidateQueries।

Controlled আর uncontrolled component?

Controlled: input-এর মান React state-এ। Uncontrolled: DOM-এই, ref দিয়ে পড়া। react-hook-form মূলত uncontrolled, তাই re-render কম।

SPA কী? CSR, SSR, SSG-র পার্থক্য?

SPA: এক HTML, route বদলায় browser-এ। CSR browser-এ render, SSR প্রতি request-এ server-এ, SSG build-এর সময়। আমারটা CSR; dashboard-ভিত্তিক app বলে ঠিক আছে, তবে SEO দুর্বল।

★ Protected route কীভাবে কাজ করে? Refresh দিলে login পেজে যায় না কেন?

PrivateRoute user না থাকলে <Navigate to="/login"> দেয়। Firebase session ফেরাতে সময় লাগে, তাই loading true থাকা পর্যন্ত Loading দেখায়। এটা না থাকলে refresh-এ ভুল করে login-এ পাঠাত।

Lazy loading আর code splitting কী?

lazy(() => import(...)) দিয়ে page-এর JS আলাদা chunk হয়, দরকারে load হয়। Suspense ততক্ষণ fallback দেখায়। প্রথম load দ্রুত হয়।

StrictMode-এ effect দুবার চলে কেন?

শুধু development-এ, cleanup ভুল আছে কি না ধরার জন্য। Production-এ একবার।

JSX কী? Browser কি সরাসরি বোঝে?

JS-এর ভেতরে HTML-এর মতো syntax। Browser বোঝে না; build tool JS function call-এ রূপান্তর করে।

Re-render কখন হয়? কমানোর উপায়?

নিজের state, parent-এর re-render, বা context বদলালে। State নিচে নামানো, React.memo, useMemo। Code-এ memo ব্যবহার করিনি, সমস্যা মেপে দরকার পড়লে করতাম।

৯. Client-side বাকি tools

Vite কী? Create React App থেকে ভালো কেন?

Dev-এ browser-এর native ES module দিয়ে file on demand দেয়, তাই শুরু ও HMR দ্রুত। Production build bundle করে minify করে। CRA এখন deprecated।

Tailwind কী? Inline CSS থেকে পার্থক্য?

Utility class দিয়ে style। Inline-এ hover, media query, design token হয় না; Tailwind-এ হয়, আর শুধু ব্যবহৃত class build-এ থাকে।

Axios কেন, fetch কেন নয়? Interceptor কী?

Axios-এ interceptor, 4xx/5xx-এ reject, আর auto JSON। Interceptor প্রতিটা request/response-এর মাঝে চলে: আমি token লাগাই আর 401 সামলাই।

VITE_ prefix কেন? সেখানে secret রাখা যায়?

শুধু VITE_ variable browser bundle-এ যায়। তাই secret রাখা যাবে না, build করা JS-এ যে কেউ দেখতে পারে।

Vercel-এ client-এ rewrite কেন লাগল?

/dashboard সরাসরি খুললে ঐ নামে কোনো file নেই, 404 হতো। vercel.json সব path index.html-এ পাঠায়, তারপর React Router সামলায়।

১০. Database

★ MongoDB কেন? SQL কেন নয়?

Request-এ nested data আছে (product, quote, inspection, payment), আর ভিন্ন device-এর field ভিন্ন, তাই document সহজে মেলে। JSON JS-এর সাথে স্বাভাবিক। Free Atlas আছে।

★ Payment আর booking আছে, তাহলে SQL বেশি ঠিক ছিল না?

সৎ উত্তর: PostgreSQL-ও খুব ভালো হতো, relation আর constraint শক্তিশালী। MongoDB-তে এই নিশ্চয়তা আমি multi-document transaction আর unique index দিয়ে নিয়েছি। Trade-off: consistency-র দায় বেশিটা application code-এ।

★ SQL আর NoSQL-এর পার্থক্য?

Table/row, fixed schema, JOIN বনাম document, flexible schema, embedding। SQL সাধারণত vertical scale, NoSQL সহজে horizontal (sharding)।

★ Embedding আর referencing: কখন কোনটা?

একসাথে পড়া হয় ও সংখ্যায় কম হলে embed: quote, inspection → repair_requests-এ। অনেক হলে বা আলাদাভাবে খোঁজা লাগলে reference: offer → job_applications। Document-এর সীমা 16 MB।

★ তোমার database design বলো।

21টা collection। মূল: users, technicians, repair_requests, service_definitions, job_applications, payments, technician_withdrawals, warranty_claims, notifications, tracking_events। Relationship: এক customer-এর অনেক request; এক request-এর অনেক offer; এক request-এ একজন booked technician।

★ Index কী? কীভাবে কাজ করে? ক্ষতি কী?

সাজানো data structure (B-tree), তাই পুরো collection scan লাগে না। ক্ষতি: write ধীর হয়, জায়গা লাগে। আমার config/database.js-এ 44টা createIndex।

Compound index-এ field-এর ক্রম কেন গুরুত্বপূর্ণ?

Leftmost prefix: {technicianId, status, createdAt} শুধু status দিয়ে খোঁজায় ভালো কাজ করে না। সাধারণ নিয়ম: Equality, Sort, Range।

Unique, partial, TTL index?

Unique: duplicate আটকায় (trackingId)। Partial: কিছু document-এ (একটাই খোলা withdrawal)। TTL: সময় হলে নিজে মোছে (email_log)। Code-এ bug থাকলেও DB আটকায়।

★ ACID আর transaction?

Atomicity সব বা কিছুই না; Consistency নিয়ম ঠিক থাকে; Isolation একে অন্যকে নষ্ট করে না; Durability commit টিকে থাকে। Booking-এ session.withTransaction। MongoDB-তে replica set লাগে।

★ Race condition কী? দুজন একসাথে একই job নিলে?

একসাথে চলা কাজের ফল সময়ের উপর নির্ভর করলে। আমি condition-সহ update করি: { _id, deliveryStatus: 'pending-pickup', technicianId: { $exists: false } }, আর transaction-এ। দ্বিতীয়জনের update মেলে না। Unique index শেষ সুরক্ষা।

Mongoose কেন নয়? তাহলে schema কোথায়?

Native driver ব্যবহার করেছি; transaction, aggregation-এ সরাসরি নিয়ন্ত্রণ। ক্ষতি: Mongoose-এর মতো তৈরি schema validation নেই। Validation নিজে লিখেছি utils/-এ (যেমন repairRequestV2.js), আর models/-এ class।

Normalization কী? MongoDB-তে denormalize করো?

Duplicate কমাতে data ভাগ করা (1NF, 2NF, 3NF)। হ্যাঁ, করি: price snapshot request-এ কপি করা, যাতে পরে দাম বদলালেও পুরনো request ঠিক থাকে।

Aggregation pipeline কী? $lookup?

ধাপে ধাপে data process: $match, $group, $sort। Admin report-এ ব্যবহার করেছি। $lookup মানে SQL-এর left join-এর মতো।

ObjectId কী?

12-byte id: timestamp (4), random (5), counter (3)। Client বা server-এই তৈরি হয়, তাই distributed-এ সংঘর্ষ প্রায় হয় না।

Replica set আর sharding?

Replica set: একই data-র কপি, primary-তে write, primary গেলে election; availability দেয়। Sharding: data ভাগ করে রাখা; capacity বাড়ায়। আমি sharding ব্যবহার করিনি, দরকার নেই।

Pagination কীভাবে করে? Offset আর cursor?

Offset: skip/limit, সহজ কিন্তু গভীরে ধীর। Cursor: শেষ _id-এর পর থেকে, দ্রুত। আমি offset ব্যবহার করেছি (যেমন models/Notification.js, models/RepairRequest.js), কারণ data কম আর page নম্বর দেখানো সহজ। Data অনেক বড় হলে cursor দেব।

১১. System design

★ পুরো system-এর architecture বলো।

Browser (React, Vercel CDN) → HTTPS → Express API (Vercel serverless, Mumbai bom1) → MongoDB Atlas (data) → Firebase (auth যাচাই) → Stripe (payment, webhook ফিরে আসে) → Supabase (ছবি) → Gemini (AI) → Gmail (email)

★ Monolith আর microservices? তুমি কোনটা, কেন?

Monolith: এক deployment। Microservices: ছোট আলাদা service, আলাদা scale, কিন্তু network, deployment, debugging জটিল। আমি একা, data কম, তাই monolith, কিন্তু folder-এ module করে ভাগ করা।

★ Serverless কী? সুবিধা-অসুবিধা?

Server-এর চিন্তা platform-এর, request এলে function চলে। সুবিধা: free tier, auto scale। অসুবিধা: cold start, memory ভাগ হয় না, দীর্ঘ connection চলে না, সময়সীমা।

★ Serverless-এ MongoDB connection কীভাবে সামলাও?

প্রতি request-এ নতুন connection দিলে connection limit শেষ হবে। connectionPromise module-এ cache করি; warm instance-এ একটাই connection। Fail হলে cache মুছে পরের request-এ retry।

★ Horizontal আর vertical scaling?

Vertical: বড় machine। Horizontal: বেশি machine + load balancer। Stateless API হওয়ায় আমার API horizontal scale করতে পারে; Vercel নিজেই instance বাড়ায়।

১০,০০০ user হলে কী বদলাবে?

আগে পরিমাপ করে bottleneck খুঁজব। সম্ভাব্য: cursor pagination, slow query-তে index, Redis cache, বড় Atlas tier, email/AI কাজ queue-তে, আর paid email service।

Caching কোথায় আছে?

Client: TanStack Query। CDN: hashed asset-এ Cache-Control: immutable। Server-side Redis নেই, দরকার পড়েনি। কঠিন অংশ হলো invalidation।

Rate limiting কী? তোমার implementation?

নির্দিষ্ট সময়ে request সীমিত করা। Public tracking: 20/মিনিট, in-memory। AI support: MongoDB-তে shared counter, কারণ serverless instance-এ memory ভাগ হয় না। সেই কারণে tracking-এর limit প্রতি instance-এ আলাদা, এটা একটা দুর্বলতা।

Real-time-এর জন্য WebSocket কেন নয়?

Serverless-এ দীর্ঘ connection সহজ নয়। Job board আর admin attention প্রতি ৬০ সেকেন্ডে poll করে। সত্যিকারের real-time লাগলে আলাদা service লাগবে। Polling, long polling, WebSocket, SSE-র পার্থক্য জেনে রাখো।

Idempotency কেন distributed system-এ জরুরি?

Network ব্যর্থ হলে retry হয়, Stripe webhook একই event একাধিকবার পাঠাতে পারে। payments.sessionId unique আর idempotencyKey দিয়ে একবারই কাজ হয়।

CAP theorem কী?

Network partition হলে consistency আর availability-র মধ্যে একটা বেছে নিতে হয়। MongoDB-কে সাধারণত CP ধরা হয়।

Single point of failure কোথায়?

Firebase, Atlas বা Stripe বন্ধ হলে সেই অংশ থামে। DB বন্ধ হলে ensureDatabaseReady 503 দেয়; email ব্যর্থ হলে মূল কাজ থামে না।

Cron কী? 0 12 * * * মানে?

Minute hour day month weekday। প্রতিদিন 12:00 UTC, মানে বাংলাদেশে সন্ধ্যা ৬টা। Vercel Cron /cron/pickup-reminders call করে।

১২. Security

★ XSS কী? React কীভাবে রক্ষা করে?

Page-এ ক্ষতিকর script ঢোকানো। React {value} escape করে। আমার client code-এ dangerouslySetInnerHTML নেই।

★ CSRF কী? তোমার project-এ ঝুঁকি আছে?

Browser নিজে cookie পাঠায় বলে অন্য site থেকে request করানো। আমি cookie নয়, Authorization header ব্যবহার করি, তাই এই আক্রমণ সাধারণত কাজ করে না।

★ NoSQL injection কী?

{"email": {"$ne": null}} এর মতো object পাঠিয়ে query বদলানো। উপায়: type চেক, input validate। ঝুঁকি থাকে JSON body-তে, তাই server validation জরুরি।

★ IDOR কী? কীভাবে আটকিয়েছ?

অন্যের id দিয়ে তার data দেখা। Login-ই যথেষ্ট নয়, প্রতিটা controller-এ দেখি user owner, assigned technician, না admin। Email নেওয়া হয় verified token থেকে, body থেকে নয়।

Password কীভাবে store হওয়া উচিত? Hash আর encryption?

Salt-সহ ধীর hash (bcrypt, scrypt, Argon2)। Hash একমুখী, encryption ফেরানো যায়। Password Firebase-এ থাকে, আমার DB-তে নয়।

Client থেকে আসা দাম বিশ্বাস করো?

না। পরিমাণ server DB থেকে নেয়। Client-এর validation শুধু UX।

Stripe webhook অন্য কেউ call করলে?

constructEvent raw body আর STRIPE_WEBHOOK_SECRET দিয়ে signature যাচাই করে; না মিললে reject।

Private ছবি কীভাবে সুরক্ষিত?

Bucket private, স্বল্পমেয়াদি signed URL। Link ফাঁস হলেও অল্প সময়ের জন্য।

Tracking page-এ login নেই। নিরাপদ?

Code অনুমান করা কঠিন: 128-bit random (crypto), আর rate limit। ক্ষতি: code যার কাছে সে দেখতে পারে, তাই সংবেদনশীল তথ্য সেখানে দেখানো হয় না।

১৩. Testing ও deployment

★ Unit, integration, e2e-র পার্থক্য? তোমার কোনগুলো?

Unit: একটা function। Integration: কয়েকটা অংশ একসাথে। E2E: user-এর মতো browser থেকে। আমার server test আসল HTTP আর MongoDB-তে (integration), Playwright e2e। Client-এ unit test নেই।

CI/CD কী? তোমার আছে?

CI: প্রতি push-এ test (GitHub Actions, আলাদা MongoDB container-এ)। Deploy স্বয়ংক্রিয় CI-তে নেই, হাতে করা হয়। তাই পুরো CD নয়।

Git: merge আর rebase? fetch আর pull?

Merge history রাখে, rebase সরলরেখা করে। fetch শুধু আনে, pull = fetch + merge।

Development আর production data কীভাবে আলাদা?

আলাদা database name (MONGO_DB_NAME) আর আলাদা env। CI-কে Atlas-এর credential দেওয়া হয় না।
